# Low-density hard-surface development plan

Updated 2026-10-09. Development candidate: `research-evidence-host-dev.22-r1`, protocol `0.2.0`.

## Current scope

The workbench develops plugin-owned domain operations and CLI-orchestrated complete work units for a bounded low-density, quad-oriented subdivision workflow. The current validated evidence is concentrated in a single-hole rounded plate. Further optimization of that practice object is paused; a higher-level junction case has now been investigated, with the bounded results and unresolved failures recorded below. Source-cage integrity, edit provenance, evaluated geometry, actual observation coverage, recovery, and intended-use qualification are separate gates.

This is a development roadmap, not a production certification or a claim of general commercial modeling capability. A repository push does not install the plugin, validate a new native operation, or qualify an asset for delivery.

## Acceptance model

- Source and editing: complete topology, connectivity, loops, edit locality, controlled face growth, and protected originals.
- Evaluation: fixed subdivision settings and identity-linked source/evaluated geometry. Finite sampled surface differences describe that comparison; they are not nominal dimensional errors or a guarantee over a continuous surface.
- Visual review: identity-matched unoverlaid views, actual surface normals where relevant, adequate multi-direction reflection coverage, and worst-region inspection. A passed job or matching hash cannot replace sufficient observation.
- Delivery: save/reopen, dependency recovery, frozen holdouts, documented limitations, and intended-use acceptance.

Maintain separate technical pass, geometry failure, insufficient-observation, not-run, and qualification states. Historical failures remain historical failures even when a useful output was preserved. Do not relabel an earlier failed outer batch as successful because a later review recovered one result.

## Longer roadmap

Candidate directions include adjacent holes and slots, thin-wall boxes and lids, stepped revolved parts, round-to-square transitions, curved-surface openings, and modular assemblies. These are a capability map, not a mandatory curriculum order. The current junction investigation does not establish those additional directions; choose later practice scopes explicitly and introduce a bounded number of new variables. Add unseen combination holdouts only after implementation is frozen; a case used for tuning becomes regression evidence and needs a replacement holdout.

The film/product route requires editable source geometry, evaluated high-resolution results, and shot-appropriate shape and surface review. The game route separately requires controlled low-poly derivation, UVs, fixed triangulation, bake/cage and normal-tangent conventions, exchange reopen, LOD, and target-engine checks where applicable. These routes are not yet complete.

Arbitrary mesh repair, manufacturing-grade accuracy, unrestricted parameter combinations, universal asset coverage, and broad commercial qualification are not current claims.

### Next stage: diagnosis and reviewed design

1. Preserve the completed and failed terminal records, baseline identities, protected invariants, and original acceptance thresholds. Distinguish the old topology's final accepted coordinates from older inputs and the replacement reference.
2. Diagnose the three separate questions using saved evidence: whether the combinatorial structure is valid, why the current reference fails geometric requirements, and why the frozen discrete assignment did not yield a continuous feasible solution. Existing evidence does not identify a unique cause among assignment choice, conservative bounds, initialization, and geometric representational limits.
3. Prepare a bounded design or diagnostic proposal before another trial. Specify the intended question, affected reference or method, protected scope, expected evidence, and stopping conditions. This checkpoint does not prescribe a new solver or authorize another model execution.
4. Obtain the required approval for any new reference, changed topology or dimensions, alternate matching, seed, optimization batch, or execution route. Historical acceptance of an appearance reference and permission for a completed one-shot run do not transfer to these changes. Authorization for source testing and publication does not itself authorize modeling or another numerical trial.
5. Only after the relevant reference and execution scope are approved, run the corresponding complete domain/CLI work unit and review its actual geometry and visual evidence. Do not restart the same failed LP, expand the budget, relax thresholds, or replace the comparison denominator merely to report progress.

A failed initializer and a bounded solver-reported infeasibility are useful research results. They justify a diagnostic/design checkpoint, not a production-readiness claim or a conclusion that the overall geometry problem is impossible.

### Public-source and evidence hygiene

Public changes may contain reviewed reusable implementation, domain/CLI interfaces, synthetic fixtures, generalized failure semantics, protected-correspondence methods and bounded roadmap conclusions. Remove hard-coded private locations and case payloads from both code and tests before publication. Check provenance and redistribution suitability for included dependencies or adapted implementation.

Do not publish private model files, actual source/evaluated coordinates, reference images, design specifications, case-specific adjacency and identity payloads, saved cost matrices or matchings, restoration archives, personal execution paths, Library identifiers, conversations, approval records, credentials, or login state. Existing audit files are not automatically safe public fixtures; use synthetic substitutes. Preserve private evidence separately without using its existence as public qualification.

## dev.22-r1 implementation scope

The public research-evidence adapter is independently implemented generic HOST
code, not a complete migration of the research junction work units or their
exact CC solver. Its grid check uses candidate vertices only, not the research
curvature coverage method. Source/model identities and linear candidate
reconstruction are checked; self-intersection is not implemented. Even all
implemented checks passing yields overall incomplete. See
[the exact contract](research-evidence.md) for limits and statuses.
