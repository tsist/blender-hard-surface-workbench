# Sparse source-bound subdivision diagnostic

The explicit `source_bound_sparse_diagnostic_v1` profile extends the existing
`hardsurface subdivision diagnose` work unit to authenticated sparse sources.
It is a read-only development diagnostic. It does not enable the sparse
constructor's `quality.stage: full` route or establish complete shape acceptance.

The request pins one saved source by bytes/SHA, one native object UUID, its full
actual non-cosmetic modifier settings and caller-supplied panel reference values.
It requires levels `[0,1,2,3]`, `export_geometry: true` and `render.enabled: false`.
Generic diagnostic settings and the older observation-bound surface export are
not mixed into this profile. The opt-in dev20 sparse observation binding is a
separate HOST-only adapter; see [sparse surface observation](sparse-surface-observation.md). The original modifier and source file are not
edited or saved. Only an owned clone receives explicit per-level overrides.

Source attestation uses the real native registry, authored face identity,
complete parent slots and per-face semantic labels. The bore domain is derived
from authenticated face provenance and checked as a closed-wall annulus in the
actual consistently oriented body. Sparse support does not replace an old sector
literal with a new literal, infer faces by proximity, or guess evaluated ancestry
from array order. Evaluated labels must transport each real source face to its
fixed-level descendants with the original oriented adjacency intact.

Source-loop checks use the current authored native structures. Closed interface
chains with poles remain distinct from regular opposite-quad edge loops. An
inserted loop's identity, actual edges, crease values and expected valence remain
verifiable without imposing the old constructor's loop cardinalities.

The report exports actual sampled mesh vertices, real edges and polygons at
every level, together with explicit source/evaluated semantic bindings. Native
analysis triangles are labelled separately from the actual polygon mesh. Indices
in different levels are not presumed to correspond. These fields support source
versus evaluated wire inspection without rendering.

The existing finite surface-distance samples, bounds and volume screens remain
diagnostics with their stated coverage. L0 is the control baseline; L1 and L3
describe behavior around the formal L2 target. A failed L0 screen does not replace
the L2 result, and a better L1 or L3 result cannot stand in for L2. Execution and
preservation success do not assign complete shape acceptance.

Approved criteria without an implemented and bound measurement remain `not_run`:
independent bore diameter/center, the prescribed angular plane-section samples,
independent outline and edge-roundover radii, the frozen flat-region mask, and a
calibrated pixel silhouette. The old vertex-station witness is not a substitute
for a plane-section ray test. A single surface-distance number cannot silently
close those missing checks. No source fitting, normal repair, highlight rendering,
or production qualification is performed by this diagnostic.

The sparse profile permits a declared sampled process-tree RSS budget of 1–3 GiB;
the previous profiles retain their existing defaults. This is not hard OS memory
isolation. Geometry, time and artifact limits are checked independently. Run the
first source pair sequentially, retain each complete job and its measured resource
receipt, and stop on execution, binding or resource failure without silent retry.

The entrypoint is the candidate's bundled `hardsurface-cli`. An installed global
wrapper is not assumed. Candidate source archives and passing HOST tests convey
no installation, native execution or user shape approval.
