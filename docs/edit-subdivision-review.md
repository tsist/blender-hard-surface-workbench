# Bounded edits with actual SubD comparison

This development work unit combines existing protected editing and independent reopening with source-bound before/after diagnosis. The workflow accepts one `insert_sparse_strip` patch or one bounded independent parameter-edit category on one saved sparse-panel feature. It does not change geometry algorithms or add native operations.

## Public entry points

Use the candidate's own `hardsurface-cli`:

- `hardsurface describe --section edit-review`
- `hardsurface edit-review plan --request REQUEST`
- `hardsurface edit-review run --request REQUEST`
- `hardsurface edit-review resume --request REQUEST`

The versioned `hardsurface.edit-review` request embeds the ordinary source-cage edit request, exact reference approval descriptor, and complete source-bound before-diagnosis request. Both bind the same saved file. The workflow accepts no unknown fields, hidden cache, rendering, fitting, extra edit attempts or implicit source migration. The diagnostic profile must explicitly contain the actual source modifier and L0–L3 exports. The constructor support domain remains the existing constructor's bounded domain.

Plan verifies source/reference/implementation identities and reports limits; the existing guarded native source inspection must still validate the saved design before construction. A successful plan is not a geometric or native execution qualification.

## Stages and recovery

The first run executes before diagnosis, existing edit with independent reopen, after diagnosis, then HOST comparison. Its upper bound is six serial native processes: one, four, one, zero. Both original files and diagnostic clones retain the established source-protection mechanism. The after diagnosis binds the saved candidate SHA and actual target/modifier from the independently reopened edit receipt. Before and after native bindings must join the native edit witness, so another object in the same file cannot silently become the comparison source.

Accepted stages have immutable commit receipts with exact artifact hashes. The public job status/result and workflow report persist progress. Resume checks source, reference, runtime, implementation, request and accepted artifact identities, then continues the same work unit. Unknown child status, a partial commit, missing evidence or conflicting bytes requires reconciliation; no new request ID or automatic native retry is created. Completed stages are reused. A failed batch remains evidence, not cleanup permission.

Aggregate and child resource limits both apply during native execution. The aggregate includes the Python host's observed RSS, active native descendant RSS, accumulated active elapsed time, retained work-unit files, serial process reservations and declared system memory reserve. These are sampled abort limits, not hard memory isolation or a promise to catch every transient peak. Separate invocations and copies elsewhere are outside this single work unit's file accounting and must be included in a caller's batch budget.

## Comparison meaning

`subdivision-comparison/1.0` validates the complete existing native export schema, world-mm arrays, actual triangulation, semantic parent transport and source modifier profile. Each side samples every vertex and native triangle centroid against the other side's entire triangle surface. A dependency-free BVH prunes triangles using bounding boxes; it does not match vertex indices or approximate with nearest vertices.

Reports retain both directions, maxima and localized nearest-surface witness pairs, all parent and surface-role coverage, measured boundaries, and own-L0 pole and control-loop neighborhoods. Source parent slots and pole indices remain local to each model. Region summaries are source-domain samples to the whole target, not semantic face matching. A nearest-surface pair is not a material-point displacement.

The caller's bound panel reference tolerance only counts finite samples above that reference. It never changes execution success into shape acceptance or triggers fitting. Complete finite sampling does not bound unsampled interiors, continuous Hausdorff distance or an analytic subdivision limit. Source coordinate preservation is a separate edit invariant and does not establish SubD preservation.

A completed work unit leaves shape review pending. Actual visual review, highlights, continuous-limit proof, calibrated silhouette and production qualification remain unasserted or not run. Readable views can be made from the retained actual exports; numerical completion alone does not certify appearance.

## Validation boundary

Neutral HOST tests cover changed topology on the same surface, known offsets, bidirectionality, actual closest-triangle witnesses, malformed semantic evidence, parser bounds, cancellation, cumulative budgets, stage recovery and unknown submissions. Existing native artifacts may be read for parser and numerical regression; that does not count as native qualification of this new candidate. Exact candidate execution requires its own bounded native evidence.

## dev19 bounded parameter-edit extension

Workflow receipt version 1.1 retains the strict 1.0 request envelope. In addition
to the existing single insertion, one or two `set_dimension` patches may drive
exactly one category on one explicit saved sparse-panel feature: hole radius
(the diameter-edit category), hole center, thickness with the already saved
`fixed_bottom` or `fixed_midplane` datum, or outer `edge_bevel` roundover.
Dimension labels are not permissions: the inspected saved program resolves the
semantic paths. No-op-only edits, combined categories, unused dimension patches,
multiple features/steps, sketches, policy changes and unsupported geometry fail
closed. Native authored-scope validation still verifies the complete bounded
constructor domain before mutation. This is independent-baseline coverage, not
arbitrary composition qualification.

The existing parameter verifier now emits exact before/after native bindings and
raw source-cage impact: predeclared affected vertices, allowed coordinate axes,
affected faces, actually changed and unchanged vertices, and protected vertices
and faces. Protected coordinate axes and connectivity retain existing exact
checks. Thickness can intentionally affect all height coordinates; unchanged
regions can therefore be empty. These are source-cage facts, not preservation
claims for the evaluated SubD surface. Outer-roundover-only edits also retain the
existing exact protected-hole region signatures. Comparisons retain this impact
alongside actual L0–L3 finite surface differences. Shape review stays pending.

No constructor algorithms, installed plugins, global settings, rendering or
production-acceptance gates change. Each independent workflow still admits at
most six serial native processes and never retries a failed child implicitly.

Parameter requests require an explicit `after_panel_reference`, changing exactly
the same single nominal category as the accepted edit; tolerance, reference frame
and unrelated nominal fields stay fixed. This prevents after diagnostics from
silently measuring a changed diameter or center against the original design.
The workflow does not infer world references from local object parameters.
Insertion requests keep this field null and retain the original reference.
