# Native structural identity integration candidate

Implementation design inherited from `structural-native-dev.5`; current candidate is `structural-native-dev.6`. The parent passed 27 native identity/fault and independent-reader cases, then stopped during the first full-workunit diagnosis. This new repair is not natively run or qualified. See source-bound-subdivision-measurement.md for the failure and repair boundary; exact-source approval is required before any native execution of this version.

## What changed

The existing fixed 24-control sharp single-hole / 48-control outer panel now authors logical vertex and face identities during construction. Identity addresses describe patch cells, bore samples, explicit grid/band/corner aliases and named profile knots. They are not raw indices, nearest-point matches or coordinate hashes. All five previous numerical fixtures retain their exact legacy arrays, provenance, crease values, control-loop records and construction SHA in host comparisons.

A separate authorship SHA and schedule revision flow from `quad_geometry.planning_evidence` to native creation. Core requires the host's exact authored hash before binding a newly created object's stable object/data IDs. The geometry construction hash continues its old meaning; identity metadata has its own authority.

The native bridge's opt-in already-oriented path verifies from_pydata coordinates as the exact IEEE float32 transport of authored metre coordinates and verifies complete face connectivity before assigning identities. Other constructors retain their old materialization path. Actual POINT/FACE INT slots are resolved through strict semantic tables, with actual polygon provenance and actual EDGE/FLOAT crease values. The actual native edge set must exactly equal polygon-derived edges, preventing omission of loose or duplicate edges.

Persisted identities, parameter/author schedule, source receipt metadata, full modifier context and object-local/world transform binding are checked again on extraction. Binding may transition from a new unbound object to one registered object/data/source identity only once. No missing-ID migration, automatic repair or nearest matching occurs.

## Core lifecycle

- Plan preparation automatically requires `structure_identity` for authored SubD steps
- Rebuild/resume validates actual structure and a separately held scene registry before accepting old targets or ports
- All before witnesses and declared edit plans are captured before any managed target is removed
- Creation binds the exact host-authorship SHA, source/job descriptor and object/data identity; edits are checked against the pre-build plan
- Final and checkpoint checks save full structural evidence sidecars; compact receipts reference those files
- Artifact acceptance verifies actual status, external saved registry, object/data identity and all four kernel signatures; it does not accept metadata-only or host-kernel evidence as native proof
- Independent reopen recomputes the actual native structure against the externally expected snapshot/registry, including hidden generated authored targets
- Loss of a settings flag cannot remove an object from required checks if native attributes or registry membership still identify it

Existing source protection, complete job supervision and snapshot/non-target checks remain in force. No alternate runner replaces the existing production work-unit implementation.

## Explicit edit scope

Hole X/Y/radius uses an authored dependency set of 160 vertices. Thickness requires an explicit `edit_datum`:

- `not_requested` or omitted: thickness changes reject; hole-only/no-op edits remain possible
- `fixed_bottom`: retain z_min; 496 designated vertices may change only Z
- `fixed_midplane`: retain the exact thickness midpoint; 992 vertices may change only Z

Both datum modes are host-tested. The earlier read-only integration design v1 described only fixed-bottom thickness; fixed-midplane is an explicit development addition to support the proposed midplane-invariant editing requirement. It is not native qualification or approval of any caller design.

The edit proof independently checks target-coordinate roles as well as protection: matching parameter metadata alone cannot justify incorrect in-scope geometry. Topology, crease attributes, authored schedule and total semantic identity sets remain fixed. Outline/frame/topology changes reject this editing path. Outer-roundover editing is additionally permitted only when an explicit fixed bore-support width is present; the coupled legacy branch still rejects it. Future expansion needs its own bounded implementation and evidence.

## Reordering boundary

Logical author identities, the host kernel and native extraction support storage reindexing when correct slots/provenance are carried. The whole-job preservation layer deliberately retains exact snapshot comparison. Reordering a previously saved user source relative to its generated baseline may therefore reject as a manual edit. This candidate does not silently relax material/non-target/manual-edit protection or advertise an automatic reordered-source migration.

## Unverified and unsupported

No Blender run, source-native edit, independent native reopen, visual observation, holdout or production qualification has been performed for dev.6. Parent dev.5 native results cannot qualify this changed implementation. The prepared native fault driver is test code, not evidence. Its positive/negative producer and separate-reader modes must be authorized and actually run; native faults can produce different earlier rejection codes than mocks, which must be investigated rather than relabeled as passing.

Native extraction is object-local millimetres under Blender scene scale_length 1.0. Float32 transport precision is distinct from design tolerance. Generic self-intersection, evaluated shape/highlights, source file guards and non-target preservation retain their own checks; the kernel cannot replace them.

The previously published execution schema bounds edge_bevel to at most 1 mm. This candidate accepts at most 2 mm only for the SubD panel route; other routes retain the 1 mm bound. Acceptance by the schema is not construction qualification. A new explicit subdivision_cage.bore_support_width option separates bore support from outer roundover. Its branch uses fixed_support_half_gap_guards_v1 to avoid degenerate near-core grid bands; nominal design, logical topology and crease policy remain separate. Omitted width preserves all five legacy results exactly. The width must be positive, no larger than the hole radius, and its compensated ring must lie strictly inside every fixed-frame side. Existing clearance, angle and aspect gates remain unchanged.

Actual plan-declaration binding is a separate read-only helper with explicit entity mappings. Unsupported interfaces/minimum-clearance claims reject; neither binding evidence nor a valid proposal authenticates user approval or grants construction authority.

## Fixed-support branch and E4 proof

The explicit-width branch has host tests for a bounded approved reference and independent diameter, position, midplane-thickness and outer-roundover variants. A combined variant remains rejected by the unchanged bore-buffer geometry gate; independent successes are not a continuous-domain or arbitrary-combination claim. Technical support width/frame selection is external project configuration, not a universal default.

For outer-roundover edits, the pre-build contract identifies the outer affected elements and nine actual semantic hole regions. Their complete coordinates, connectivity and crease signatures are independently compared before/after; matching vertex counts are insufficient. Coordinate, role and partial-metadata tamper cases reject. Native fixed-width coordinate/loop attestation also checks the actual author schedule, and require_fixed_support=True can pin the caller's intended inspection mode.

All these additions remain native/evaluated-surface/visual unqualified until their exact frozen implementation is authorized and run. No threshold was widened to rescue a failed construction, and no approved nominal reference dimension was changed.
